# MoPlayer

Windows 10/11 x64 本地视频播放器与分类管理工具。

## 运行

解压 `MoPlayer-portable-win64.zip`，双击 `MoPlayer/MoPlayer.exe`。保留整个目录，不能单独复制 EXE。不需要安装 Python、Qt、VLC 或 FFmpeg。不需要管理员权限。程序目录必须可写；请不要放在 Program Files 等受保护目录。

启动不自动导入旧目录、不自动播放。左侧拖入一个文件夹或使用导入按钮，双击视频播放。左右分隔线可以拖动。历史视频、历史文件夹、收藏列表分别有入口。

快捷键：空格播放/暂停；X 下一个；Z 同目录上一个；左方向键或 A 后退五秒，右方向键或 D 快进五秒，均支持长按并限制在有效时长内；Enter 切换仅视频全屏；Esc 优先关闭弹窗，其次退出全屏；Q 标签；R 评分；W 添加收藏。文本编辑和弹窗优先处理输入。Ctrl+D 仍为删除，不触发快进。W 不切换取消，取消收藏请在收藏列表操作。

**Ctrl+D：删除并自动播放下一条。** 鼠标单击选择的视频优先；没有选中视频时使用当前播放视频。视频全屏使用正在播放的视频。默认移入 Windows 回收站，不执行永久删除兜底；多标签视频会回收数据库登记的全部硬链接入口，成功后同步移除历史、收藏、标签、评分和进度。回收站恢复文件不会自动恢复已删除的元数据。未登记的外部硬链接不在删除范围内。

删除成功后，按照被删除视频原来的播放上下文执行 X 的规则自动播放下一条；删除选中的未播放视频时使用其所在的浏览目录上下文。没有下一条时停止，不循环。当前媒体与本应用的缩略图解码器会先释放文件占用。外部程序禁止删除或回收失败时不自动换片，保留未完成任务；解除占用后可再次按 Ctrl+D，或在「更多 → 文件任务」重试。多入口部分完成时保留剩余入口和元数据；异常退出后沿独立 `deletion_jobs` 日志继续恢复。文本编辑、模态弹窗和下拉菜单优先，长按 Ctrl+D 不会连续删除多条视频。

## 界面与背景设置

界面采用紧凑工具栏和双栏工作区：顶部为历史、收藏与设置，左侧为目录，右侧为播放画面及控制栏。蓝色用于主要操作、播放进度和选中状态，默认背景为中性灰。左右分隔条可拖动。目录、历史和收藏直接显示 **180×120** 缩略图，缓存画布为 240×160。系统缩略图、归档任务和帮助位于右上角「更多」菜单。

点击右上角「外观」选择 PNG/JPG/WebP/BMP 背景图，调整背景显示强度后点击「保存外观」。预览期间可以取消或按 Esc 撤销，也可恢复默认背景。图片副本及设置保存在 `data/appearance`，采用相对文件名，跟随便携目录移动；原图不被修改。超大图片会等比缩小至最长边 3840；超过一亿像素的图片不接受。

EXE、窗口和顶部品牌使用云璃 Q 版同人表情图标。完整 PNG、ICO 和生成说明见源码包 `assets/README.md`；不是官方表情包。构建脚本自动导出多尺寸 ICO 并嵌入程序，无需额外安装依赖。

## 标签大类、小类与自动评分

按 Q 打开标签界面。上方搜索框查找已有标签，底部输入框新增标签（Enter 只新增，不自动应用）。左侧复选框选择当前视频标签，最右侧选择「大类 / 小类」。新标签和旧版平级标签默认是大类；小类可拖到大类所在行，应用后缩进显示在大类下。右键标签也可以直接选择「归入某大类」，不必拖动。小类改回大类会移出原父级；有小类的大类需要先移出其小类才能改类型，避免产生三层结构。

标签名称全局唯一，一个小类只能属于一个大类，目前支持两级。类型和归属是全库共用的；改变某个角色的所属大类，会同步全部已归档且受影响的视频，不改变其他视频的评分。搜索、勾选、类型选择和拖动都只改变草稿，点击「应用标签」才提交，取消或 Esc 不修改文件与数据库。未归属的小类必须先拖入大类才能应用。

大类初次打开默认折叠，只通过名称前的三角展开或收起；双击名称、键盘展开键、拖动悬停和搜索均不自动展开。新增标签、修改类型或归类小类时，保留已有手动展开状态及原视口位置，不再展开全部大类或跳回顶部。

小类路径为 `E:\我觉得是学习资料\评分\大类\小类\文件名`。例如八分视频选择「绝区零」「爱丽丝」「黑丝」，将爱丽丝归到绝区零后，入口为 `8分\绝区零\爱丽丝\8分 绝区零（爱丽丝） 黑丝 原名.mp4` 和 `8分\黑丝\8分 绝区零（爱丽丝） 黑丝 原名.mp4`。父子同时选中时，父级由子类隐含，不再在「绝区零」根目录增加重复入口；只选大类时仍直接放在大类目录。所有入口继续使用硬链接，共享同一视频内容、UUID、历史、收藏、进度与缩略图。

文件名先列出带子类的大类，格式为 `大类（小类）`；同一大类下多个子类使用 `大类（子类一、子类二）`。之后列出其他独立标签，组内和独立标签均沿用自然排序，不采用用户点击先后顺序。永久原名仍单独保存，重命名不会叠加旧前缀。原播放快照只更新显示名，不重新排序。

**标签及全局文件同步全部完成后自动弹出评分界面。** 主区为 1～10 分十个按钮，点击一个即确认，不再使用下拉框；另保留独立「0 分」和「未评分」操作，已有评分以蓝色显示。Esc 或「取消」允许稍后按 R 评分，不会自动清除已有分数。新评分会再同步所有标签入口的评分目录及文件名前缀。标签界面和评分界面打开期间不强制暂停，文件实际迁移时安全释放并按原进度/暂停状态重载。自动评分始终绑定本次标签操作的视频，即使它在弹窗期间自然结束，也不误评下一条。

全局同步使用独立批次日志 `hierarchy_jobs`，逐视频仍使用原归档日志 `jobs`。新入口先存在，再提交该视频分类，最后清理旧入口；所有相关视频完成后才原子提交公共标签结构并显示成功。部分失败时不弹评分，明确保留未完成批次，菜单「更多 → 文件任务」可查看和重试；启动会恢复此前已明确提交的批次，恢复全部成功后再请求评分。恢复不会自动加载目录或播放历史。未完成全局迁移会暂时阻止新的分类、评分归档和删除，以免破坏恢复入口；部分视频可能已先完成移动，界面会显示真实状态而非伪报全库成功。

## 播放顺序与默认值

- 文件夹和视频分别按自然名称排序，目录树先显示文件夹，再显示视频；目录展开按需生成视图索引。
- 浏览目录和播放上下文是两个对象。替换浏览目录不切换视频；双击新树视频才建立新播放快照。
- X 在当前目录视频末尾后，仅搜索当前文件夹的后续同级文件夹。目标目录先检查直接视频，再按自然顺序递归子文件夹。找不到时不循环、不向祖先扩展。Z 永不跨目录。
- 导入根目录中的视频到达末尾时，同样允许进入它的一层后续同级目录：导入时只捕获同级目录顺序，真正按 X 或自动连播时才异步扫描目标子树，不扩大左侧浏览树，也不继续向更高祖先扩展。历史视频和收藏恢复其当前有效所在目录作为新的扫描根；历史文件夹只加载目录。
- 首次播放从零开始；再次播放恢复上次进度。自然看完后进度归零，下次从头播放。默认音量 80%。第一版不提供倍速和字幕界面。
- 归档确认前保持播放状态。确认后采用安全重载：保存进度、释放 VLC 文件句柄、后台归档、按原暂停状态续播。大文件跨卷复制期间播放等待，界面显示实际任务状态。
- 单次拖放一个文件夹。扫描跳过重解析点（符号链接、junction 等），保留普通目录层级。相同导入根内的大目录在后台扫描，支持取消；已完成结果才替换树。

## 归档与数据保护

归档根目录固定为 `E:\我觉得是学习资料`，结构为 `评分目录\标签名称\视频文件名`。评分目录是 `未评分` 或 `0分` 至 `10分`。取消全部标签保留到当前评分的 `未分类`。未归档视频修改评分只保存数据库，首次 Q 确认才归档。

归档文件名为 `实际评分 全部标签 原文件名.扩展名`，以空格分隔，标签沿用自然排序。例如原名 `abc-123.mp4`，评分 8 分且选择「白丝」「标签2」，两个标签目录的文件名统一为 `8分 标签2 白丝 abc-123.mp4`。多个入口仍是硬链接，共用一份视频内容。未评分使用 `未评分`；取消全部标签使用 `未分类`，例如 `0分 未分类 abc-123.mp4`。零分不会写成未评分。

评分或标签确认后，同时更新全部入口的目录、文件名、数据库显示名和当前浏览行；原播放顺序不因改名重新排序。数据库单独保存 `original_name`，每次均从永久原名重建前缀，不会出现 `9分 … 8分 … 原名` 的叠加。老版本记录在下一次确认分类时使用原有文件名初始化，启动不批量改动现有视频。原始文件名本来含有评分或标签字样时视为原文，不猜测删除。现有已归档视频可再次通过 Q/R 确认应用新规则。

完整名称超过 Windows 单个文件名 255 个 UTF-16 单元限制时，会明确拒绝并保留原文件，不静默截掉原名或标签。发生同名不同视频冲突时，保留原有文件并为新目标追加 ID/序号。未归档视频单独评分仍只保存数据库，首次 Q 确认后才归档并改名。恢复日志包含新名称与原名，文件入口先就绪，再事务提交名称和分类，最后清理旧入口。

归档前检查目标 NTFS 文件系统，并实际探测硬链接权限。多标签入口是正常视频文件硬链接，不使用快捷方式，不静默降级成重复复制。首次成功归档清理已登记的来源入口。未知的外部硬链接不会被任意搜索或删除。

文件身份采用 Windows 卷标识、文件索引与创建时间组合，数据库视频 ID 使用独立 UUID。路径不是永久身份。所有硬链接入口共用评分、标签、进度、收藏和内部缩略图。路径消失或被其他同名文件替换会报错，不进行同名猜测；应用外部移动且未重新扫描的文件可能需要用户重新导入其实际位置。

任务流程：持久计划 → 安全暂存入口（同卷硬链接；跨卷复制并 SHA256 校验）→ 全部目标入口验证 → SQLite 元数据事务 → 清理旧入口 → 完成。只有新入口存在并提交数据库后才删除来源。任务中断后启动自动重放；失败通过“归档任务”查看并重试。旧路径身份或内容状态改变时停止清理。不要在归档过程中用其他程序修改视频内容。

同名不同文件追加视频 ID 与序号，绝不覆盖。标签拒绝非法字符、路径分隔符、设备保留名、尾点/空格、大小写重复及 `未分类` 保留名。标签长度上限 80 字符；极长完整路径仍可能被系统组件拒绝，程序会保留来源并报告失败。

归档中正常关闭会等待任务结束。强制结束或断电后可自动恢复；不要自行清理 `.moplayer-staging`，这是失败恢复用的安全暂存目录。失败时可能暂时同时存在来源和目标，这是保护数据的中间状态，并非成功归档。磁盘故障导致数据库不可写时应保留现场、恢复磁盘可写性再启动。

## 数据目录

程序旁 `data/library.sqlite3` 保存：

| 表 | 内容 |
|---|---|
| videos | UUID、当前显示名 name、永久原名 original_name、可为空的整数评分、收藏、毫秒进度、播放时间、标签、归档状态 |
| paths | 一个视频的多个有效路径及文件身份 |
| folders | 独立文件夹导入历史 |
| tags | 已确认使用过的标签字典 |
| jobs | 归档计划、阶段、错误、更新时间 |
| tag_layout | 全局大类/小类类型及小类父级；视频保存规范化叶子选择，父级从这里推导 |
| hierarchy_jobs | 全局结构草稿、相关视频冻结目标与逐视频完成标记、错误及更新时间 |

SQLite 使用 WAL 和 FULL 同步。进度每五秒、换片及正常退出保存。`data/thumbnails/<视频ID>.jpg` 是异步生成的共享缓存；`data/moplayer.log` 为轮转日志；`application.lock` 防止同目录双开。备份请正常关闭后复制整个 data 目录；视频文件需要另外备份。数据库不是视频内容备份。

## 编码与缩略图

播放内核为 VideoLAN libVLC 3.0.21 x64，随包带其编解码插件。扩展名仅用于扫描候选文件，实际能否播放由容器、编码、配置、文件完整性及硬件决定。实际测试的容器/编码组合和系统缩略图结果见 `TEST_RESULTS.md`；不能据此宣称所有 MP4、MKV 等文件都可播放。加密/DRM 内容不在支持范围。

软件内部缩略图由随包 FFmpeg 异步生成并按视频 ID 缓存，统一为 **240×160 像素**，宽高均至少 120 像素；保持原视频比例并补边，不拉伸画面。旧尺寸缓存自动重建。Windows 文件资源管理器使用系统 Shell 缩略图提供程序，与 VLC、软件内部缩略图是独立链路，显示尺寸由 Windows 的大图标/超大图标视图设置决定。普通运行不会自动注册系统组件；需要全局支持时点击「更多 → 系统缩略图」单独启用。验收使用 `IShellItemImageFactory` 的 THUMBNAILONLY 模式（不允许用普通图标冒充缩略图），并针对实际归档硬链接测试。

**在软件中查看：导入文件夹，展开目录后，每个视频行直接显示 180×120 的缩略图，无需选中、双击或先播放。历史视频和收藏列表也逐行显示相同尺寸的缩略图。** 文件夹保持紧凑行高，视频行高 136；左侧可以拖宽或横向滚动。后台仅为可见视频生成缩略图，最多两个解码任务并发，同一视频多个硬链接共用缓存；生成中和失败分别显示明确占位提示。此功能不依赖资源管理器的缩略图组件。

「系统缩略图」采用 Icaros 3.3.6 官方便携包，启用时校验官方 SHA256，将组件及依赖全部部署到 `E:\tools\videoplayerenv\plugins\Icaros-3.3.6`。其 COM 注册属于系统配置，不能当作解压免安装功能；首次启用可能要求 UAC。注册表和 Windows 自身的缩略图缓存位置由系统管理，不能迁移到工具目录；Icaros 独立缓存已禁用。资源管理器还需关闭“始终显示图标，从不显示缩略图”，并使用大图标或超大图标视图。此组件目录启用后不可删除或随意改名。

## 构建

所有本项目开发工具、依赖、下载、临时文件和缓存位于 `E:\tools\videoplayerenv`：

| 路径 | 内容 |
|---|---|
| python/tools | NuGet Python 3.12.10 x64 及 site-packages |
| runtime/vlc-3.0.21 | 官方 VLC Windows ZIP 运行库与插件 |
| downloads | Python NuGet ZIP、VLC ZIP |
| cache | pip、Python 字节码、PyInstaller、pytest 缓存 |
| temp | 临时和单元测试文件 |
| build、build-resources | 打包中间文件 |
| verification | 实际播放、GUI、归档、缩略图验收样例及报告 |

完整依赖见 `requirements.txt` 与实际版本锁定清单 `dependencies.lock.txt`。新环境运行 `powershell -ExecutionPolicy Bypass -File bootstrap.ps1`，脚本仅在指定环境根内下载、解压和安装。手动准备方式：从 `https://www.nuget.org/api/v2/package/python/3.12.10` 下载并解压到 `python`；运行 `python/tools/python.exe -m pip install -r requirements.txt`（设置 PIP_CACHE_DIR、TEMP、TMP 到上述隔离目录）；从 `https://download.videolan.org/pub/videolan/vlc/3.0.21/win64/vlc-3.0.21-win64.zip` 下载并解压到 runtime。

运行源码：`E:\tools\videoplayerenv\python\tools\python.exe app.py`。

运行核心测试：`python.exe -m pytest tests -q -o cache_dir=E:\tools\videoplayerenv\cache\pytest --basetemp=E:\tools\videoplayerenv\temp\pytest`。

构建：在项目目录运行 `powershell -ExecutionPolicy Bypass -File build.ps1`，输出 `dist/MoPlayer/MoPlayer.exe`。目录部署包含全部原生依赖，打包时的固定路径不用于便携版运行。打包结果可整体 ZIP 压缩分发。

生成交付压缩包：使用独立 Python 运行 `package_release.py`，会生成 `release/MoPlayer-portable-win64.zip`、`release/MoPlayer-source.zip` 和 `SHA256SUMS.txt`，并检查 ZIP CRC。便携包最终启动文件就是 `MoPlayer.exe`，并非 Python 脚本启动器；其相邻 `_internal` 运行库目录需要整体保留。

便携自检：`MoPlayer.exe --self-test E:\tools\videoplayerenv\verification\portable`。自检会显示测试窗口、生成视频样例并在输出目录执行隔离归档，报告为 `report.json`；不会使用正式归档根目录或正式数据库。详细测试结论和未验证范围必须参照交付测试报告。

缩略图可见性自检：`MoPlayer.exe --thumbnail-test <新的可写输出目录>`，验证目录、历史和收藏中无需选择即可显示实际 180×120 画面，输出截图及 `thumbnail-report.json`。升级时正常关闭旧 EXE 后覆盖程序和 `_internal`，保留原 `data` 文件夹；构建脚本同样保留已有 data，不清空历史、收藏或评分。

## 全局视频缩略图支持

本机已启用 Icaros 3.3.6，并为 36 种常见视频扩展名、`MoPlayer.Video` 和 `Applications\MoPlayer.exe` 配置统一缩略图处理程序，覆盖任意目录中的新旧视频。无需先导入播放器，也无需逐个文件执行缓存修复。文件夹需使用大图标或超大图标；旧窗口可关闭后重新打开，让 Windows 重新按需提取。

## 2026-11-04 标签胶囊与五颗心评分

本次标签界面取代旧版标签树与类型下拉框。普通标签点击选中/取消；右键「设为父标签」，再把普通标签拖到父胶囊上即可归类。点击父胶囊才显示或收起其子标签，新增、拖放和搜索不会自动展开其他父类，并保留滚动位置。右键可移出子类、改归其他父类；父标签自身需要单独选中时使用右键「选中父标签」。底部输入加号新增，最后「应用标签」统一提交，取消或 Esc 放弃草稿。

## 2026-11-04 单父类展开、嵌套与删除

同一时间仅展开一个父标签，打开「3D」会收起原来展开的「游戏」。父标签现在也可拖入其他父标签，并保留原有子孙；点击子父标签后显示其直接子标签，「返回上级」用于返回。归类、搜索和新增仍不自动展开其他父类；禁止把标签放入自身或其子孙。
