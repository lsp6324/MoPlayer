# MoPlayer 架构与演进规则

本文件与根目录 `AGENTS.md` 是后续开发约束。架构边界纳入 `tests/test_architecture.py`，与普通 pytest 一起执行；纯应用协议另有不加载 Qt/VLC 的测试。文档描述真实实现，尚未迁出的职责明确列为待办。

归档总开关保存于 StorageSettings.archive_enabled（内存 enabled），旧配置缺省保持启用。原子保存成功后才更新有效状态，失败保持旧配置。TagMigration 可显式提交 metadata_only：为所有受影响视频冻结纯元数据模式，仅更新评分／标签及全局结构，不解析本地路径、不创建归档／清理任务；已有 archived、路径、身份及入库时间不变。恢复只认每个视频冻结的模式，不读后来切换的开关；旧计划保留原文件任务语义。此底层扩展独立验证和提交。

删除记录与本地文件的选择冻结在 deletion_jobs.plan 中：DeletionManager.forget 写入 delete_files=false，仅事务移除该视频记录、路径引用并终止其旧入口清理，不调用回收器、不访问或修改本地文件；原 submit 继续回收全部已登记有效入口。恢复读取原模式，缺少模式的旧任务按原文件回收语义执行；未完成任务不能被另一种模式覆盖。该底层扩展独立验证和提交。

标签全局重命名沿用 TagMigration 的持久批次：submit 可接收旧名到新名的映射，先校验目标、重名与结构，再替换全部视频的标签引用。父标签改名保留子树；未归档记录只更新元数据，已归档记录复用安全归档同步路径。映射及最终逐视频选择一起冻结进 hierarchy_jobs，恢复按原根目录和规则继续，不会把重命名当成删除旧标签再创建新标签。该底层变更有独立引用、身份、原位文件及故障恢复回归。

## 源码目录

源码位于 `src/moplayer/`，其中 `application/` 和 `infrastructure/` 保留原职责，所有界面模块位于 `gui/`。根目录 `app.py` 只委托 `moplayer.app.cli`，模块入口与 EXE 使用相同参数分派。工具位于 `tools/`，原生验收位于 `tools/verify/`。下文保留逻辑模块名：`application/*`、`infrastructure/*` 相对源码包，无目录的 UI 模块相对 `gui/`，`app.py`／`runtime.py`／四个既有底层模块相对源码包。

导入统一使用完整包名；架构测试根据物理路径构建完整模块图，再归一成原逻辑名执行既有边界，额外检查根目录只保留启动入口、新包和工具必须归类。四个底层模块只移动及更新导入，身份、事务、归档、删除和设置规则不变。源码／打包资源根和源码压缩包收集规则同步调整，见 [开发文档](DEVELOPMENT.md)。

## 依赖方向

`窗口装配 / UI → application 协议与状态`；`窗口装配 → infrastructure 适配器 → 既有 Store / 文件服务`。

应用流程通过构造参数接收数据查询、任务调度和 UI 生命周期的适配入口，不反向导入具体窗口。视图只绘制、收集输入、表达意图。低层 UI 基础组件不导入布局、主题应用、主窗口或功能浮层。

## 状态与完成协议

- `TagDrafts` 拥有草稿；编辑器保存可编辑视图，提交时复制快照。提交期间不修改已提交快照，失败不会确认基线。
- `Operation` 在应用线程完成一次。`Outcome` 明确成功、取消或失败，失败携带是否已有持久恢复任务。工作线程负责计算，Qt 调度适配负责交付结果。
- `UserActions` 协调保存与后续动作；通过 before_action 等待文件流程实际对账后的 completion，再确认草稿。待保存时合并选择请求，关闭请求优先。成功执行后续动作，失败或取消保留草稿并取消依赖动作。
- `FileTasks` 协调暂停缩略图、释放文件、运行文件服务和恢复媒体的统一生命周期；媒体恢复与文件任务成功分别核对。
- `FileTasks` 在工作线程中调用注入的 prepare 端口，统一停止缩略图文件占用，再运行既有服务。窗口保留 VLC 句柄释放/重载、导航忙碌显示和旧版存储根目录的适配，不决定各文件任务完成后的刷新范围、草稿对账或连播。
- Classification、Deletion、Recovery 分别持有结果规则，通过明确的服务、记录刷新、播放和通知端口协作。FileNotice 是展示输入；窗口不根据它再查询任务、确认草稿或决定下一条视频。依赖草稿提交的操作等待结果协调完成，媒体恢复或状态更新失败不会确认成功。
- 部分失败后显示实际已提交的名称；分类/归档失败或取消不会放行依赖的换片、关闭。删除后的导航作为单独结果，失败或取消保持停止。恢复包含普通归档任务与标签批次涉及的 ID，只有数据库已不存在的删除身份会被排除。
- 标签、评分及按收藏目录归档使用持续播放流程，FileTaskPolicy 不释放媒体；播放、暂停、定位和进度保存继续运行，分类编辑串行准入。删除、重命名、设置整理和旧持久任务恢复继续按需要释放媒体；不能把所有任务的 stop() 统一移除。
- `PlaybackSession` 拥有续播意图和未确认跳转；UI 时间轴只负责平滑显示，不能成为播放器实际状态的来源。
- `PlaybackSession.source` 表示当前实际打开的文件路径，分类后不改成新的逻辑归档路径；释放媒体或打开下一片时更新保护。FileTasks.media_released 与 Window 的文件/导航 busy 分工不同；PlayerView 分别接受播放阻塞和分类编辑阻塞，不能因后台分类冻结进度。
- `PlayerView` 拥有播放区及其展示组件。PlayerInfo、最后一次呈现的 PlaybackStatus、时长、音量和倍率选择仅用于展示，不决定视频身份、任务准入或进度持久化。实际播放命令、状态读取和文件任务规则仍由窗口适配与应用会话处理。
- 静态图片与视频共用同一浏览快照、稳定 ID 和 Z/X 切换顺序。`core.media_kind` 只按已登记扩展名分类，`Window.current_kind` 是该事实的唯一所有者；图片经 `ImageLoader` 在工作线程解码后交给 `PlayerView.present_image`，窗口既不启动播放内核，也不轮询其状态、不写续播进度。图片模式的展示差异（进度条与播放按钮禁用、徽标显示“图片”）由 `present_transport(still=True)` 表达，分类、评分、收藏、改名和全屏继续可用。缩放、平移和适应窗口只属于 `ImageView` 的展示状态，不参与任务准入或持久化。
- 空闲播放区由 `Wordmark` 承担，替代原来的播放图标与“导入文件夹”按钮：`Mo` 用 Bahnschrift Bold、`Player` 用同族 Light，前置强调色箭头，全部按当前 DPI 矢量绘制。它只接收 `apply_theme` 传入的深底文字色与 `colors_for('dark', accent_source)` 的强调色，因为空闲区背景始终是深色画面；导入入口保留为左侧加号与拖放，不恢复空态按钮。
- 主题及全屏切换通过明确的状态刷新信号取得最新播放状态，由同一入口绘制播放按钮。标题/收藏/评分只更新展示；拖动时间轴只预览，释放时发出比例意图，窗口按实际时长请求一次定位。VLC 倍速请求失败保持已接受的选择。
- 全屏组件只接收 Qt 宿主、PlayerView、画布和分隔器，不读取窗口业务属性。全屏继续复用同一控制栏，不重新创建或移动原生视频宿主；播放区的普通标题和全屏标题共用同一份展示输入。
- `LibraryController` 拥有浏览和异步资料库任务。新目录扫描取消旧目录扫描，旧回调不能发布快照、历史目录或播放请求。用户取消保留原目录；取消按钮反映全部资料库任务，单个任务结束不能隐藏仍在工作的其他任务。
- 文件页拖放经 DropList 的单 URL / 本地路径检查与注入的 can_import 端口后表达路径意图；窗口通过 UserActions 等待保存，再调用 LibraryController.import_path。它与 load_folder 共用浏览任务、稳定 ID 定位及完成结果，不增加另一组扫描状态。文件夹拖放不主动播放，单视频加载父目录并续播目标；显式拖放任务被后续播放选择取消，纯文件夹选择器浏览仍独立于播放。执行时目标消失、扫描失败或身份不匹配均不替换旧目录/播放。
- 浏览快照与窗口的播放快照分开。主动选片取消旧的待播放请求和导航，但纯目录浏览可继续；文件任务与关闭取消全部资料库任务。最近/收藏打开和删除按稳定 ID 捕获意图，异步期间的列表重排、换页或取消选择不会改变目标。
- `LibraryView` 拥有左侧控件、当前目录与各目录的选择/滚动锚点。FolderModel 只投影当前目录，文件夹在前、视频在后，全部卡片保持同一左边距；视频位置通过 LOCATION_ROLE 保留原快照逻辑索引，硬链接同 ID 的多个入口仍可独立选择。最近/收藏沿用 VideoListModel。模型通过插入、删除、移动和 dataChanged 通知更新，元数据刷新不清空列表，删除不重排播放快照；分页分别保留选择和滚动锚点。
- 目录双击、路径和上一级在已加载快照内只切换可见投影；未知目录由 LibraryController.browse_directory 调用注入的单层扫描端口，沿用 browse 任务槽的取消和过期保护，遵守文件任务准入，失败保留原视图。目录结果以 directory 事件交付，视图保留各目录选择／滚动；不保存草稿、不触发播放、不记为新导入。路径可返回到磁盘／共享根，显式导入仍清除旧展示历史，并由 LibraryChange.location 提供一次性初始定位。原 TreeModel/DropTree 及目录树样式已删除，不保留兼容别名或另一套树形状态。
- 磁盘变化单独调用 LibraryController.refresh_browsing，复用资料库工作调度，后台任务不显示前台扫描控件；同一刷新合并，主动导入取消旧刷新。控制器按旧浏览对象及文件任务准入检查晚到结果，只发布 contents 和新的浏览快照，不写导入历史、不修改播放快照、不请求播放。刷新期间较新的元数据保留，普通进度/评分刷新只有数据库实际名称变化时才改条目名称，避免将磁盘外部改名显示恢复成旧名。
- FolderModel 的入口键与 LOCATION_ROLE 分离；同 ID 多硬链接按名称区分入口，唯一身份的外部改名保留现有行键。文件/子目录变化以增删移动及 dataChanged 发布，复用最近/收藏的行协调规则，不重置模型。删除入口不猜测选择另一个硬链接；回到目录时按入口身份和名称恢复选择。当前目录删除后沿路径回到仍存在的祖先，导入根删除时为空列表，重建后自动恢复。无法完整读取时保留原可见内容并重试，通知失败不弹模态框。
- 结束后的进度统一为零；连续相对跳转基于尚未确认的目标累加。窗口关闭、换片与周期保存使用同一进度策略。

## 后续修改检查

库仅查询 archived=1 的稳定身份，多个硬链接不产生重复行。LibraryController 通过独立 catalog 任务异步查询并取消过期结果，控制筛选、成员、元数据和不可用标记；进度刷新只更新已有行，最近播放排序在缓存内调整。查询期间较新的进度不会被晚到结果覆盖。库页和文件页的选择/滚动分别由 LibraryView 保留，大集合纯排序通过 Qt layoutChanged 与稳定 ID 重映射持久索引，避免逐行移动的平方开销；插入/删除继续使用现有行协调。

筛选控件在 catalog_filter_popup.py 的浮窗内，catalog_panel.py 只保留搜索、带条件数的筛选按钮、结果数、排序和摘要；已选条件按组显示为可点击移除的胶囊，摘要与浮窗读同一 CatalogFilter。评分区分精确与及以上（gte 包含边界分并排除未评分），标签区分 AND 与 OR，标签祖先包含后代在两种模式下都成立；缺失这两个字段的旧偏好分别按 exact 与 and 恢复。列表与网格共用同一视图、模型和播放队列，切换只换排布并保留选中身份、滚动锚点和筛选，不重新查询或换片；页面、筛选排序和视图一起存入 data/library.json，非法视图值回退列表且不写盘。网格的格宽按「视口宽度 − 滚动条宽度」计算并预留滚动条位置，使滚动条出现时不会把第二列挤到下一行；滚动条按需显示，空库不出现。

启动恢复：main() 在存储就绪后调用 Window.restore_last_folder，由 LibraryController.last_folder() 从 folders 表取最近载入的根目录，再走既有 load_folder 异步扫描。只恢复到顶层、不传播放目标，因此不会自动播放；目录不可用或未完成文件任务超过重试窗口时保持空文件页。启动页固定为文件页，偏好的 page 字段仅供记录，库页不在启动时查询。

双击库行创建 CatalogContext 固定当时的 ID 顺序，不导入媒体所在目录；此后筛选或重新分类只改变结果，播放继续使用原集合上下文。删除非播放项不清空或导航播放器；删除当前项沿当前队列继续。路径不可用只标记该行并保留当前媒体，不自动删除或绑定同名文件。首次成功归档在元数据/有效路径事务中写 archived_at，后续编辑、整理和恢复不重置，旧 archived=1 且 NULL 的记录始终保留未知日期。

自定义背景覆盖顶栏、资料库、标题/播放栏和未播放的主区域。theme 根据 BackgroundCanvas 的实际图片状态推导 library_panel 半透明底层与 row_bg；不另存背景启用镜像标记。LibraryView 的视口不自动填充不透明底色，VideoDelegate 的普通行透明，选中/悬停仍保留可读底色。无图片时恢复原面板颜色。空闲区与画布使用同一坐标/裁切，不各自拉伸一份图片；播放时隐藏空闲层，原生宿主及全屏不受图片覆盖。外观预览取消、损坏图片回退、尺寸变化和强度变化均沿用同一刷新路径。

便携运行时，业务数据库、设置、日志、背景和列表缩略图在 data；Python/Qt/子进程临时文件使用 data/temp，应用默认 QSettings 使用 data/qt-settings，VLC 3 配置、数据和缓存使用 EXE 旁 portable。不会改用户 APPDATA、LOCALAPPDATA 或 USERPROFILE；应用目录不可写时明确失败，不回退到用户目录。Windows 自身的对话框历史、回收站、系统缩略图和驱动缓存由系统管理，不属于应用资料库。Qt 的显式 NativeFormat 设置不受默认 IniFormat 重定向影响，不能宣称改默认格式就重定向了所有 Qt 内部设置。

StorageSettings 在缺少 storage.json 时返回 data 同级 video，不在读取设置时创建视频目录或移动文件。默认根保存为唯一相对标记 video，其他自选根沿用绝对路径；损坏或不支持的相对配置报错，不用默认根覆盖。现有归档批次仍按原冻结目标恢复，配置修改继续由 ArchiveConfiguration 整理已归档视频。解压到非 NTFS 盘仍可播放，归档继续要求 NTFS，不隐式降级为多份复制。

可选资源管理器缩略图组件的下载、DLL、回执及注册备份由 setup_explorer_thumbnails 放在 BASE/data/integrations/explorer-thumbnails；提权脚本从 BUNDLE 取得，复制后以自身位置定位组件，不能依赖开发机盘符。只有用户主动启用才写系统注册；移动后需重新启用以更新路径。验证不能实际注册或替换用户现有系统组件。

package_release 只接收已验证的目录部署包，排除 data、video、portable 中已有内容，仅为 video/portable 写空目录；源码包包含 application、infrastructure 和测试，不打包本机证据或数据库。纯测试覆盖新安装默认、默认标记迁移、自选根保留、配置损坏与保存失败，以及发布包排除用户内容；原生 --portable-layout-test 在独立桌面检查真实临时文件、VLC 目录查询、播放、缩略图和默认归档。

## 渐进迁移范围

既有模块允许在当前边界内继续工作，新增业务应进入对应应用模块。资料库、播放区及文件任务结果协调已迁出窗口。窗口生命周期、既有文件服务内部的事务/锁与持久任务恢复一致性，仍需按具体功能逐步审查。不能通过新增窗口方法、混入类或扩大遗留许可把新逻辑继续堆入这些位置。

底层文件操作已经有事务和恢复顺序。迁移查询接口时保留这一顺序，不能把同一原子过程拆为互不协调的存储对象。数据库模式发生实质变化时，需建立独立、有版本的迁移入口及旧库升级验证。

## 自动守卫与验证

`tests/test_architecture.py` 检查模块归类、应用层依赖、基础组件依赖方向、完整生产导入图（包含函数内导入）、UI SQL、绘制中的资料库访问，以及已迁出状态和资料库/播放区控件的所有权。播放视图及浮层另有禁止具体播放器、资料库和窗口业务访问的守卫，静态图片展示组件同样纳入该规则。不得为新增功能放宽这些规则来保留错误依赖。

GitHub workflow `.github/workflows/architecture.yml` 在 push 和 pull request 时运行架构守卫、纯应用协议（含扫描、取消、过期回调和浏览/播放独立性）及资料库适配器测试，无需安装 Qt 或 VLC。该 workflow 提供持续检查；是否将其设为受保护分支的必需检查属于仓库管理设置，当前未变更该设置。

文件工作流协议测试一并纳入持续检查，覆盖冻结输入、部分失败、取消、媒体恢复失败、状态更新失败、普通归档恢复刷新，以及删除后继续/停止。窗口禁止直接提交/恢复服务或运行 FileTasks，已移除的流程入口不保留转发别名。

归档目录设置默认沿用标签、评分启用且收藏关闭。启用归档并保存设置才整理全部已归档视频，未归档视频不移动；关闭总开关则标签／评分／收藏只写元数据，所有现有路径保留；所有目录依据关闭时直接使用归档根目录。文件名保持已记录原名，标签、评分、收藏只影响元数据、目录和展示。目录依据不影响评分、标签、收藏元数据的有效性。

升级时，归档配置应用流程查找有可靠原名记录的旧归档视频，基础设施在 archive_setting_jobs 中记录原名恢复批次，复用原有安全归档子任务，在现有目录内恢复原名，不修改归档偏好。没有原名记录的保留当前名；同名不同内容追加稳定标识而不覆盖。旧 jobs、标签、设置和删除任务先按原日志恢复，然后在同一媒体释放周期内恢复原名，统一刷新实际受影响视频；不得按新命名规则篡改旧日志目标。

归档设置批次与标签结构批次、单视频归档、删除互斥，失败时保留已完成入口与旧有效配置，按持久计划继续，不能临时改用后来选择的根目录或目录依据。归档和标签批次均冻结目录规则；旧任务没有该字段时沿用原来的评分、标签布局。恢复时先完成普通归档子任务与标签批次，再恢复归档设置批次，最后恢复删除；结果统一刷新实际受影响视频。

收藏变更属于 Classification：未归档或未启用收藏目录时更新标记与列表；已归档且启用收藏目录时走文件任务，路径和收藏标记在同一视频事务中提交，失败不提前确认。播放器和侧栏入口共用这一流程，LibraryController 不再提供绕过归档的收藏写入入口。设置窗口不持有 Window 业务属性；自动边界检查约束它只使用显式应用端口。

本机完整 pytest 继续覆盖 UI、文件恢复、数据库提交失败、扫描互斥等行为。真实 UI 和 VLC 集成继续通过独立桌面检查，构建后检查打包程序。构建使用显式 `--hidden-import vlc`，对应 runtime.py 的动态原生加载入口。

手动重命名在普通标题原位输入：Enter 提交、Esc 或失焦取消，失败保留草稿并就地提示。PlayerView 按 PlayerInfo.video_id 固定展示目标，换片或隐藏时撤销编辑并隔离晚到结果。MediaHeader 不读取磁盘或业务对象；应用 Renaming 注入只读预检及提交端口，预检失败不启动媒体释放；真正操作仍由 FileTasks 暂停缩略图并按需要释放/恢复媒体。

FileRenaming 复用 jobs 表，以 action=rename 区分冻结计划，无新增数据库模式；使用 Store.file_lock 与扫描、归档、删除互斥，先完整预检所有有效登记入口，再逐入口执行 Windows 不覆盖式改名。恢复按源/目标身份、大小和修改时间确认中断位置，不依赖上次内存状态；全部有效新入口确认后，同一事务更新 name、original_name、paths 及 committed 状态。普通归档恢复跳过重命名计划，Recovery 注入专属恢复端口，在标签批次前重放，并统一刷新涉及 ID。改名不创建归档、不要求归档设置、不修改目录、评分、收藏、标签和进度；保留扩展名，已有文件或其他视频路径记录均不得覆盖。

持续分类复用 Archiver 的校验、硬链接和跨卷复制，新增计划显式冻结 defer_cleanup；TagMigration 将该选项冻结到批次再传给子任务。目标路径不变的已归档视频只事务更新元数据，不执行卷探针、暂存或创建单视频 jobs。需要改目录时先验证全部新入口，同一数据库事务提交元数据、有效 paths 和逐入口 cleanup_jobs，并移除旧路径的有效映射；普通归档 job 随即完成，清理队列不属于 pending_tasks() 默认阻塞集合。没有新标记的旧计划继续原语义重放。

cleanup_jobs 保存路径、身份、大小、修改时间和错误，schema 版本 1 在独立事务内创建。ArchiveCleanup 在 Store.file_lock 内重试；当前播放源延后，路径被后来的分类重新使用则取消旧清理意图，外部替换或占用只记错误。它从不重放评分/标签，不阻塞后续分类；Cleanup 每 5 秒在空闲时调度，也提供独立手动重试。扫描遇到已退休且未激活的路径返回原视频 ID、不重新登记旧入口；删除预检与冻结计划包含待清理入口，完成后同步结束其清理记录。这个队列保证跨卷播放来源、程序中断与连续分类都能安全收尾。
